# Аграрный formatter: локальный проект

Источник — фактический JSON из `docs/agrarian_report_contract.md` и `docs/agrarian_report_examples.json`. Код не подключён к backend, Dify или Meta. `agro.ai` не используется. Текущий аграрный маршрут отправки остаётся закрытым.

## Расчёт

`calculate(report)` читает `organization`, `college_branch`, `workflow_route`, `student.full_name`, `group.course_name`, `main_group.name`, `period.month`, `groups[].id/course_name`, `lessons[].lesson_id/group_id/date/grade`. Он **не** читает готовые `summary` и `subjects[].grade_counts`, поскольку их счётчик посещений не имеет отдельной категории смешанных отметок. Расширение backend payload не требуется: уникальные ID уроков, предметы, даты и все строки оценок уже присутствуют.

Для каждой пары `(group_id, lesson_id)` собираются все `2/3/4/5/Н`. Числовые записи считаются поштучно в предмет; занятие относится ровно к одной категории: `graded` (только числа), `absent` (только `Н`), `mixed` (числа и `Н`), `unmarked` (пустая строка синтезированного урока). Дата сама по себе не является ключом. `lesson_details` остаётся в рассчитанных данных, поэтому агрегированное Meta-представление не стирает детализацию. Если по предмету нет числовых оценок, пишется «баа коюлган эмес», а не `5: 0` и т. п. Проценты не рассчитываются.

`render_meta(calculation)` формирует пять строковых параметров и полный preview. Нормализация выполняется **после** объединения предметов и категорий: любые CR/LF, табуляции и последовательности пробелов становятся одним пробелом. Переносы абзацев находятся только в статическом BODY.

## Проект Meta BODY

Точный текст — [meta_body_draft.txt](meta_body_draft.txt). Язык: кыргызский; имя и статус шаблона пока не назначены и в Meta не проверены.

| Параметр | Значение | Источник |
|---|---|---|
| `{{1}}` | ФИО студента | `student.full_name` |
| `{{2}}` | Колледжная группа либо первичная предметная группа | `main_group.name` или `group.course_name` |
| `{{3}}` | Год и месяц | `period.month` |
| `{{4}}` | Все предметы и распределение `5/4/3/2`; пустые оценки обозначены словами | `groups` + все числовые `lessons` |
| `{{5}}` | Четыре количества уникальных занятий: числовые, `Н`, смешанные, неотмеченные | классификация `lessons` по `lesson_id` |

Локальная вместимость: до **12 предметов** и до **1024 символов полного BODY** после подстановки. Оба ограничения проверяются до выдачи параметров; превышение вызывает `ValueError`, без обрезания предметов или оценок. Это проектный guard, а не утверждение об одобрении Meta. Если будущие данные не помещаются, понадобится отдельный шаблон или согласованный способ доставки полного отчёта. При 104 проверенных студентах максимальная длина среди 103 существующих payload — 395 символов.

Полные предпросмотры: [agrarian_formatter_previews.json](../../docs/agrarian_formatter_previews.json). Четыре предмета — обезличенный реальный октябрьский отчёт. Один предмет — **проекция одного реального предмета** из этого отчёта, а не отправляемый payload отдельного студента: единственный студент с одним предметом в октябрьской выборке возвращает `skipped` по текущему правилу архивной активности. Демо смешанных отметок добавляет `Н` к занятию с числовой оценкой; неотмеченное занятие взято из реального payload.

## Проверка

`PYTHONPATH=dify/agrarian python3 -m unittest dify/agrarian/test_formatter.py -v` — mock-тесты без сети. Отдельная read-only сборка всех 104 аграрных студентов за октябрь 2026 дала 103 payload и один `skipped`; все 103 существующих payload прошли `calculate` и `render_meta` без ошибок, без внешних запросов. По ним получились 3 601 занятие только с числами, 1 005 только с `Н`, 9 смешанных и 2 747 неотмеченных. Эти числа отражают состояние данных на момент проверки, не заменяют контроль непосредственно перед будущей публикацией.
