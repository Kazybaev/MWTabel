## Модель, API, форма и правила

- `StudentProfile.parent_name`: `blank=True`, без `null=True` и без заполнения
  фиктивными именами. API принимает отсутствие поля и пустую строку; отсутствие
  поля при обновлении сохраняет имя. В форме убрано required, добавлено «Необязательно».
  Импорт сохраняет существующее имя; явно конфликтующее решение блокирует импорт.
- Миграция `0011_alter_studentprofile_parent_name_importedgradecell`: изменение
  parent_name через `SeparateDatabaseAndState` без SQL; создание новой таблицы
  `ImportedGradeCell` с уникальным ключом источник / класс / строка / колонка.
- Все предметные группы импортируются с `MON_FRI`. Отличающееся существующее
  расписание — конфликт. Основная группа — точное название `<поток>-Кибер`.
  Отсутствие/неоднозначность и другая существующая основная группа — конфликт.
  Все предметные группы, включая «Кибер», добавляются в `college_groups`;
  существующие связи не удаляются.
- Телефоны очищаются от пробелов, форматирующих невидимых символов и разделителей.
  9 цифр получают +996, 11 цифр с первой 7 — знак +. Международные номера проходят
  проверку PhoneNumberField / phonenumbers. Другие формы не угадываются.
- Копия значения со strip распознаёт 2–5 и Н, нормализует н/abs/abs. в Н.
  Пустые значения и ровно один, два или три дефиса не создают/не удаляют оценку.
  Четыре дефиса остаются неподдерживаемым значением.
- LessonRecord создаётся лишь при подтверждённых студенте, группе и дате.
  Несколько результатов на одну пару студент/дата остаются неразрешёнными.
  Отсутствие строки журнала не означает пропуск.

## Просмотр и повторный импорт

Django Admin: `/admin/tabel_app/importedgradecell/`. Доступ к просмотру только
активному staff ADMIN или superuser. Добавление, редактирование и удаление
через этот раздел запрещены. Есть фильтры по причине и предметной группе,
поиск по источнику, группе и логину. Карточка показывает исходный JSON,
координаты, хеш содержимого и nullable связи со студентом/группой/уроком.
Отдельный экран React для архива не добавлялся.

Уникальный ключ не содержит значение или заголовок. Изменение содержимого,
включая смену JSON-типа, даёт `source_cell_changed` до планирования производной
оценки. Архив и существующие оценки не перезаписываются. Позднее уточнение
связей/дат требует отдельной проверенной процедуры разрешения; повторный импорт
не является скрытым обновлением архивных записей. `--allow-partial` не разрешает
конфликты. Без него заблокированный профиль запрещает всю запись. Явно
архивируемые неизвестные даты/личности учтены как unresolved, а не потерянные данные.

## Безопасность и проверка

Dry-run — PostgreSQL `REPEATABLE READ, READ ONLY`: без INSERT и без расходования
последовательностей. Применение — одна `transaction.atomic` и блокировка таблиц,
включая новую таблицу; ORM bulk_create обходит save/M2M signals и API-отправки.
Флаги `AUTO_MONTHLY_REPORTS=false`, `REPORT_SCHEDULER_RUN_ON_START=false` задаются
до старта Django; scheduler исключает команду импорта. Конфликт запрещает запись
даже с `--allow-partial`. Приватные отчёты создаются эксклюзивно с правами 0600.

Приватные планы: `/tmp/college-plan-verified.json` и
`/tmp/college-plan-verified-repeat.json`. Они содержат идентификаторы проблемных
строк, не пароли. Результаты проверки описаны ниже после завершения тестов.

Пример безопасного dry-run после миграции **на изолированной копии**:

```bash
AUTO_MONTHLY_REPORTS=false REPORT_SCHEDULER_RUN_ON_START=false \
python manage.py import_college_seed /private/seed.json \
  --source-id college-2026-seed --dry-run \
  --expect-database tabel_import_review \
  --report /private/new-plan.json
```

Подключение к БД задаётся окружением; `--expect-database` проверяет выбранную
базу, а не переключает подключение. Не копировать эту команду с production
настройками ради тестирования миграции.
