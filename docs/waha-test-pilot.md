# Изолированный тестовый канал WAHA

WAHA test — отдельный ручной канал для проверки подготовленного текста отчёта.
Он не вызывает Dify, не меняет текущую очередь и по умолчанию выключен.

## Ограничения пилота

- Отправлять может только администратор через кнопку «Тест через WAHA».
- Выбираются конкретные студенты; размер пакета ограничен 10.
- Тестовый отчёт можно поставить в очередь только в дату последнего урока
  группы за выбранный месяц. У студента должна быть хотя бы одна запись табеля
  за месяц, но запись именно за последний урок не обязательна. Если сегодня не
  дата последнего урока или за месяц нет ни одной отметки, задание получает
  статус `skipped`; отчёт при этом будет содержать только внесённые записи.
- Все тестовые сообщения идут только на `WAHA_TEST_RECIPIENT`.
  `StudentProfile.parent_phone` никогда не используется как адрес WAHA.
- Текст отчёта содержит реальные имя, оценки и посещаемость выбранного студента.
- Не использовать этот канал для проверки пары студент/месяц, которая уже
  отправлялась или подготовлена через Dify/Meta либо WAHA production. WAHA
  production проверяет существующие тестовые попытки перед подтверждением;
  тестовая очередь остаётся отдельным тестовым инструментом и не предназначена
  для обхода production-блокировок.
- Номер получателя хранится в локальной конфигурации/секретах, не в коде.
- Повтор ранее принятого или неопределённого сообщения автоматически запрещён.
- Статус `accepted` означает только HTTP-приём запроса WAHA. Подтверждения
  доставки WhatsApp в этой первой версии нет.
- Для одной WAHA-сессии запускается только один worker; не масштабировать его
  горизонтально. Задания, оставшиеся в `processing` после аварийного завершения,
  требуют ручной проверки, автоматического повтора нет.
- Между сообщениями worker выдерживает паузу 2 секунды. Если обработка задания
  зависла в `processing` дольше 5 минут, оно переводится в `unknown`, а не
  отправляется повторно.

## Настройка локально или на сервере

Добавить переменные в защищённый `.env` или secret store; реальные значения не
добавлять в Git:

```text
WAHA_TEST_MODE_ENABLED=true
WAHA_WORKER_ENABLED=true
WAHA_TEST_RECIPIENT=+<международный тестовый номер>
WAHA_API_KEY=<длинный случайный API key для клиента>
WAHA_API_KEY_HASH=sha512:<SHA-512 hash того же ключа>
WAHA_SESSION=default
```

`WAHA_API_KEY_HASH` настраивается у WAHA, а исходный `WAHA_API_KEY` передаётся
только backend-worker в заголовке `X-Api-Key`. Не публиковать сам ключ, QR-код
или содержимое тома сессии.

Профиль WAHA не стартует при обычном `docker compose up`. Сначала отдельно
запустить только WAHA и подключить тестовый WhatsApp-аккаунт:

```bash
docker compose --profile waha-test up -d waha-test
```

Dashboard доступен только на `127.0.0.1:3001`; удалённо открой его через SSH
tunnel, а не через публичный reverse proxy. Используй сгенерированные WAHA
учётные данные и подключи именно тестовый WhatsApp-аккаунт. После подключения
запусти worker:

```bash
docker compose --profile waha-test up -d waha-test-worker
```

WAHA API доступен worker во внутренней сети Compose. В пилоте используется зафиксированный ARM-образ
`devlikeapro/waha:arm-2026.9.2`. Не переключать production на тестовый образ,
том сессии или ключ; production WAHA имеет отдельные ресурсы и настраиваемый
образ. Не обновлять плавающий тег `latest` автоматически.

Если WAHA получил запрос, но worker не смог подтвердить результат (например,
timeout или HTTP 5xx), элемент становится `unknown` и не отправляется повторно.
Сначала вручную проверить тестовый WhatsApp-аккаунт и историю WAHA.
