# Деплой раздела «Колледж»

Изменение рассчитано на production, где существуют только данные Академии.
Миграции не удаляют и не очищают существующие таблицы: всем текущим группам,
студентам и менторам назначается `organization_type = "academy"`.

## Перед деплоем

1. Создать резервную копию production-базы данных.
2. Убедиться, что применены все предыдущие миграции `tabel_app`.
3. Проверить план: `python tabel_project/manage.py migrate --plan`.

## Порядок деплоя

```bash
pip install -r requirements.txt
python tabel_project/manage.py migrate
cd frontend
npm ci
npm run build
```

После сборки перезапустить backend-процесс обычным способом окружения.

## Проверка после деплоя

```bash
python tabel_project/manage.py check
python tabel_project/manage.py showmigrations tabel_app
python tabel_project/manage.py test tabel_app
```

Проверить вход администратора, переключение «Академия / Колледж» и убедиться,
что старые группы отображаются только внутри Академии. Первые сущности Колледжа
создаются через существующие формы после переключения кабинета на «Колледж».

## Откат

При проблеме сначала вернуть предыдущую версию приложения. Не откатывать
миграции с удалением колонок на production: новые nullable/default-поля не мешают
старой версии, а удаление схемы может привести к потере уже созданных данных Колледжа.
